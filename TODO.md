## Почему нынешний Windows CI долгий

Workflow последовательно запускает `cargo test`, затем отдельный `cargo build --release`. В `Cargo.toml` для dev-профиля у зависимостей задан `opt-level = 3`, а release использует `opt-level = 2`, `lto = false`, `codegen-units = 16`. Cargo хранит артефакты разных профилей раздельно, поэтому после долгой сборки тестовых зависимостей release-вариант снова компилирует свой граф. Кэширование Cargo в workflow есть, но hit для этого run не подтверждён. Live-лог показывал разрешение 572 пакетов и последовательную компиляцию Bevy/wgpu. На run #25 тесты заняли 43 мин 20 сек; release-компиляция началась в 07:46 UTC и всё ещё выполнялась на 08:04 UTC. Последний прочитанный лог в 07:57 UTC показывал `bevy_core_pipeline v0.20.1`; точного ETA нет. Общий timeout job — 240 минут, это предел, а не прогноз.
